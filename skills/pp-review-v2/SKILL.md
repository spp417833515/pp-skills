# /pp-review-v2 — 审查 + 回顾(自我攻击审查 5 维 + 跨任务进度盘)

## 定位

```
本体 · 成果审查  对本次产出做 hostile 自我攻击审查 5 维 + 真实测试复核 · 发现必落记账
附加 · 任务回顾  读 task 状态机盘点近期任务(独立模块 · 删除 §三不影响审查本体)
不是 LLM 夸自己干得好 · 是切 hostile reviewer 找漏洞
审查发现必落记账(见 §Store 接线)· 不口头略过
```

## 调用方式

```
/pp-review-v2 <任务名>     审查本任务产出 + 末尾附近期回顾
/pp-review-v2 --recap      只回顾近期任务进度(不审代码)
```

## 接口契约(移植先看这 · 三段式见 /pp-pipeline §五)

| 项 | 内容 |
|---|---|
| 输入 | 本次产出代码 + 任务目录 3 份 MD + clarify 三件产物③(无 → §7+对话目的,降级不阻断) |
| 输出 | `证据/审查报告.md` + 发现闭环(must 全解才放行) |
| Store 接线 | ppwiki review / task 模块 · 记账①②③ → 见 §Store 接线 |
| 缺依赖行为 | 无 ppwiki → 发现落审查报告 §1(标「未入库」)· 修复闭环照走;附加模块 §三 直接跳过 |

## 一、自我攻击审查(先过目的关 · 再审代码 5 维)

```
切换角色 = hostile reviewer · 默认"代码有问题" · 逐维举证驳倒
```

**维0 · 目的达成(前置硬门 · 红线4 用户目的=硬标准)**:对照 clarify 三件产物③「预期效果」+ 验收标准 §7 退出标准(无三件产物 → 用 §7 + 对话目的;都无 → 提示先 /pp-clarify-v2)→ 建的 == 要的?用户能做到 ①原始诉求 / ③预期效果 吗?达不成 = must(代码再干净也不放行):**实现没做到目的 → 退 /pp-execute-v2;方案本身就达不到目的 → 退 /pp-plan-v2**。

**代码质量 5 维(逐维找茬)**

| 维 | 攻击问题(往死里挑) | 对照源 | 落点 |
|---|---|---|---|
| **代码** | 违反红线 1-8?三层越级/倒置?50 行写成 100 行?手术刀越界? | 项目公约 AGENT.md | 记账② |
| **数据源** | 双信源并存?类型转换漏到业务层?字段语义与现有冲突? | 验收标准.md §2 | 记账② |
| **封装** | 调用方不止一行?职责不单一?重复造轮子(生态/项目已有)? | 验收标准.md §4 | 记账② |
| **调用** | 调用链有断点?隐藏副作用?跨模块约束被破坏?import 上层? | 验收标准.md §3 | 记账② |
| **逻辑流程图** | 画 mermaid「实测调用链」· 与 执行方案.md §6「设计调用链」逐节点比对偏差;再对照 §0.0 上下游影响表逐节点核验预测(预测「不受影响」实测却受影响 = 方案级错误) | 执行方案.md §0.0 + §6 | 证据/审查报告.md |

> **真实测试复核**:重跑 验收标准.md §5/§6 关键命令 + 真实链路 · 确认 execute 的"全绿"不是侥幸 · 非 mock。

## 二、审查流程(6 步)

```
Step 1 · 进阶段 → 记账①
Step 2 · 先过维0 目的达成(对照 clarify 三件产物③)→ 再 5 维逐维攻击 · 每条发现 → 记账②
Step 3 · 真实测试复核(重跑 §5/§6 关键验收命令 · 记实际输出)· 挂 → 退 /pp-execute-v2(全绿是侥幸)
Step 4 · 取待办修复(修完必复审 · 闭环)→ 记账③:
         取待办 → 逐条修根因 → 重跑该维攻击 + 真实测试 →
         通过才销账;仍挂 → 不销账 · 退 /pp-execute-v2
Step 5 · 写审查报告 → 证据/审查报告.md
         (5 维结论 + 实测 mermaid 流程图 + 真实测试输出 + 残留风险)
Step 6 · 全绿(无 must 级未解;should 可延 → 记入审查报告残留风险)→ 末尾按公约交付 5 段给结论(结论/验证/未处理/风险/下一步)
         + 附「近期回顾」→ 下一步 /pp-sync-v2
```

## 三、任务回顾(附加模块 · --recap 或审查末尾附 · 可整节删除不影响审查本体)

> 本节额外依赖 ppwiki task 模块(记账④)· 无 ppwiki 直接跳过 · 移植时随 §Store 接线一并处置。

| 任务 | 阶段进度 | 做了什么 | 没做 / 遗留 |
|---|---|---|---|
| PPAgent纯MCP核心重构 | 根因✓ 方案✓ 执行🔄 审查○ 归档○ | 工具封顶根治 · 启动器双栏 | 审查未过 · 未同步 wiki |
| 工具对管闭环 | 根因✓ 方案✓ 执行✓ 审查✓ 归档⊘ | 全链路打通 | 漏归档(卡 archive) |

> 高亮「卡在哪个阶段」的任务 + 一句话建议下一步喊哪个命令。

## 四、证据留存(Step 5 · 落盘)

```
.pp/wiki/当前任务/[任务名]/证据/审查报告.md
├ §1 五维攻击结论(代码/数据源/封装/调用/逻辑流程图 · 各维 ✓/✗ + 证据 file:line)
├ §2 实测调用链(mermaid · 供 /pp-sync-v2 直接灌 wiki「逻辑流程图」字段)+ §0.0 上下游预测核验(逐节点 ✓/✗ · 全局图需修订处标明)
├ §3 真实测试输出(命令 + 实际结果 · 去敏)
└ §4 残留风险(触发/影响/缓解)
```

## Store 接线(ppwiki · 移植时改写/删除本节 · 方法论正文零 ppwiki)

| 记账点 | 时机 | op |
|---|---|---|
| ① | Step 1 进审查阶段 | `task --advance_phase {task_id, to_phase}` |
| ② | Step 2 每条发现 | `review --submit {维, 严重度, 证据 file:line, 建议}` |
| ③ | Step 4 待办闭环 | `review --list_pending` → 修根因复审通过才 `review --resolve` |
| ④ | §三 任务回顾 | `task --list` → 逐个 `task --get` 读 phases 状态机 |

- op / 参数以 `ppwiki('system --help', {module:'review'/'task'})` 为准 · 禁凭记忆
- 离线降级:②③ 改落审查报告 §1(标「未入库」)· 闭环照走;④ 直接跳过 · 禁静默

## 六、失败 / 边界

| 情况 | 处置 |
|---|---|
| 5 维查出 must 级问题 | 必修根因 · 修完才放行(不口头记一笔放过) |
| 真实测试复核挂 | 退回 /pp-execute-v2 · execute 的"全绿"是侥幸 |
| 实测链 ≠ 设计链 | 偏差入审查报告 · 判是实现错还是方案错 · 错在方案 → 回 /pp-plan-v2 |
| §0.0 上下游预测失准(预测「不受影响」实测受影响) | 方案级错误 → 回 /pp-plan-v2 修 §0.0+§0.4 · 全局图修订记入审查报告 §2 |
| review op 报错 | `ppwiki('system --help',{module:'review'})` 核对 |
| --recap 无近期任务 | 提示"近期无 active 任务" · 正常退出 |

## 七、不做的事

- ❌ 不夸自己(切 hostile · 默认有问题)
- ❌ 不口头略过发现(必落记账② · 离线落审查报告标「未入库」)
- ❌ must 级问题不修就放行
- ❌ 不用 mock 冒充真实测试复核
- ❌ 不写业务代码以外的顺手重构(手术刀)
- ❌ 不替 /pp-sync-v2 写 wiki(只产审查报告供其取用)

下游:/pp-sync-v2(取审查报告 §2 实测流程图灌 wiki)
全链路 / 目录结构 / 所有权 → /pp-pipeline
